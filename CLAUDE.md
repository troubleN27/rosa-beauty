# Rosa Beauty

Telegram bot for salon appointments + web admin panel. One Neon Postgres database shared by both.

- Requirements: [docs/PRD.md](docs/PRD.md)
- Technical spec: [docs/SPEC.md](docs/SPEC.md)

## Work rules

- Work strictly by stages from SPEC section 11, one stage at a time. Do not start the next stage without an explicit command.
- After each stage: run checks (bot: `ruff check`, `pytest`; admin: `npm run build`, `npm run lint`), compare with the stage's "Done when", commit, report, ask before moving on.
- Do not add features outside SPEC or anything from PRD section 8 ("out of scope").
- No new libraries beyond SPEC section 1 without approval.
- Secrets only in `.env` files (git-ignored). Never print connection strings or tokens.
- All bot texts in RU and EN via `bot/app/i18n/*.json`; no "demo"/"test project" wording anywhere.

## Structure

```
db/migrations/   SQL migrations (generated by drizzle-kit + custom ones) — the only source of truth for the schema
db/seed.sql      initial salon data
admin/           Next.js (App Router, TS), Tailwind + shadcn/ui, Drizzle, Better Auth
  src/db/schema.ts       Drizzle schema (app tables), auth-schema.ts (Better Auth tables)
  src/db/index.ts        Neon connection (server only)
  drizzle.config.ts      writes migrations to ../db/migrations
bot/             Python 3.12, aiogram 3, SQLAlchemy async + asyncpg, APScheduler, uv
  app/main.py            entry point (long polling)
  app/config.py          settings from .env
  app/db/engine.py       async engine (direct Neon URL, SSL)
```

The bot never changes the schema: schema changes go through `admin/src/db/schema.ts` → `npm run db:generate` → `npm run db:migrate`.
Things Drizzle cannot express (e.g. `bookings_no_overlap` exclusion constraint) go into a custom migration: `npx drizzle-kit generate --custom --name=<name>`.

## Commands

Admin (`cd admin`):
- `npm run dev` / `npm run build` / `npm run lint` / `npm run typecheck`
- `npm run db:generate` — generate a migration from the schema
- `npm run db:migrate` — apply migrations to `DATABASE_URL`
- `npm run db:seed` — apply `db/seed.sql` (idempotent)

Bot (`cd bot`):
- `uv sync` — install dependencies
- `uv run python -m app.main` — run the bot
- `uv run ruff check` / `uv run ruff format`
- `uv run pytest`

## Environment

- Windows, PowerShell.
- Neon project `rosa-beauty` (aws-eu-central-1), branch `dev` for development, `main` for production.
- Bot uses the direct (non-pooled) Neon URL; admin uses the pooled URL.
